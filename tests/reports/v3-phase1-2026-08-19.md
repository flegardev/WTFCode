## Security and failure isolation

- Imported repository code was not executed.
- Analyzer commands use argument arrays with shell bypass.
- Working directories are resolved and validated before launch.
- Child environments contain only explicitly allowlisted inherited keys.
- stdout and stderr are isolated and capped independently.
- Windows process timeouts are enforced without relying on blocking pipe reads.
- A failed provider produces an independent failed result while successful providers still produce a graph.
- Persisted provider messages are control-character stripped and capped at 500 bytes.

## Explicit limitations

- Only `wtfcode-native` is an active analyzer provider.
- PHP-Parser, Tree-sitter, ts-morph, SCIP, Ctags, ast-grep, Semgrep, Gitleaks, OSV, Syft, Grype, and CodeQL adapters are not implemented.
- Deep/security/maximum profiles are defined but not yet wired to additional providers.
- Analyzer registry UI, graph LOD, feature intelligence, change guard, caching, incremental scans, resumable jobs, and product modes remain future phases.
- The project directory is not a Git worktree, so no implementation commit or clean-worktree assertion is available.
