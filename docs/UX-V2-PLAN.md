# Premium UX 2.0 audit and execution plan

Baseline: `d399e8e`, verified clean against `origin/codex/saas-mvp`, 28 October 2026. Work branch: `codex/premium-ux-v2`. All fourteen original screenshots were visually inspected; preserve them in place.

## Findings

The overview opens with technical counts, a generic scanner summary, duplicate navigation and a long stack of panels. Ask's primary answer is a normalized-evidence count, and its evidence locations are not links. Small graphs stretch two groups across a tall canvas. Change impact puts risk labels, counts and raw prompts ahead of a useful decision. File explanations are long headings. Dashboard secondary hover colors conflict with inherited CSS. Legacy hardcoded green/dark surfaces and very small type undermine light mode and mobile readability. Dashboard raw finding instances and overview grouped review themes have different counts but the same label.

## Implement in reviewable stages

1. **Understanding first:** evidence-derived, cautious project briefs and useful deterministic answer structure; compact overview with four clear questions; actionable source links; conversational change intent with an explicit target; file explanations with optional technical sections. No external AI, fabricated purpose, schema rewrite or security relaxation.
2. **Consistent product shell:** shared functional navigation, accessible controls and loading/copy/error states, compact graphs and text alternatives, useful dashboard/empty state, verified public-sample preview and honest pricing. Keep advanced graph/Change Guard/Git/source features reachable. Apply tokens to both themes.
3. **Verify and deliver:** fresh disposable localhost database, new real registration/import/worker scan; existing security and queue suites; Chromium flow, keyboard and touch targets, contrast/a11y checks and all seven widths (320/375/390/430/768/1024/1440) in both themes. At least sixteen separate new screenshots and a side-by-side baseline gallery. Report measured results and remaining limits without a production-readiness or willingness-to-pay claim.

## Boundaries

Preserve authorization, CSRF, sessions, quotas, leases, default-closed private access, evidence sanitization and clone cleanup. Do not execute imported code, merge, deploy, activate billing or change production. A public preview uses exported verified evidence, not a simulated scan or a new unmetered API. Cloud deployment hooks must not be triggered for this review branch without authorization.
